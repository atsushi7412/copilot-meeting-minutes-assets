# 配布原本の達成基準と自動化の範囲

ゴールは、受講者が原本を導入し、自分の業務に合わせて育てながら、会議直後に確認・共有できる品質の議事録を作れること。配布原本には、作成手順、SSOTのひな型、導入方法、演習、評価方法を含める。本資料は講師・保守者向けである。

## 完了段階

本資産の完了段階は次の4段階で扱う。上位の段階を下位の結果だけで認定しない。

1. 構造検証済み：ファイル一式・文字数制限・frontmatter・相対リンクの解決・ZIP構造を機械的に検査済み。
2. 原本の独立審査済み：作成手順・評価基準・ケース設計を、担当とは別の技術系AI（Codex／Opus統括配下の独立審査体制）が独立に技術審査済み。これは人による意味査読（本番相当の人の目での最終校正）ではない。両者を取り違えないこと（R3是正・統合指摘#7で明確化）。本v0.2で人による意味査読・人の採点校正は未実施。
3. Copilot実機検証済み：実際にMicrosoft 365 Copilotでエージェント・スキルを作成し、評価ケースを実行して採点済み。
4. 研修・実会議検証済み：研修受講者による実施、許可された実会議での再現を確認済み。

この版（v0.2）で到達するのは①②まで。③④は未実施であり、実施結果を保証値として扱わない。評価基準・判定方法は [評価基準](../trainer/evaluation-checklist.md) による。

## この版で用意する体験

必要なデータが参照可能になった後、会議を指定する1回の指示で初稿を得る構成を標準とする。終了を検知して無操作で起動する構成の選択は未確定であるため、自動起動フローはこの版に実装しない。

達成を分けて扱う。ファイル一式が整っていることは原本作成完了（①相当）、Copilotで評価を通ることは動作検証完了（③相当）、対象組織の実会議で再現できることは実務移行完了（④相当）である。

## 会議終了から完成までの時間

会議終了から書き起こしが参照可能になるまで、利用者の指示から初稿まで、人が確認して共有可能になるまでを分ける。書き起こし未取得の状態で会議設定から議論を補い、早く完成したことにしない。

生成5分以内・人の確認5分以内・初回設定30分以内・重要事項95％以上・重大誤り0件は受入目標であり、未測定の時点で保証値として配布しない。

## 無操作の自動生成を追加する場合

起動の候補は会議終了そのものと、書き起こしの参照可能化の検知である。会議終了時点では資料がそろわない場合があるため、後者を含む取得待ち・再試行の設計が必要となる。

Copilot Studio等で、対象開催回の照合、書き起こし取得、会議設定取得、SSOT取得、生成、保存までの経路を設計する。権限、実行主体、管理者設定、利用コスト、保存先を対象組織で確認する。イベントトリガーを含む自律実行では課金条件が変わるため、Microsoft 365 Copilotの対話利用と同一条件とは扱わない。

同じ会議での重複生成を防ぐため、開催回IDと書き起こし版を保存する。取得待ちは間隔と打切り条件を決め、失敗時に未完了を知らせる。初稿の保存と参加者への配布は別工程とする。自動配布が必要な場合は、対象者・内容・実行条件を決めたうえで追加する。

自動化の受入試験では、正常生成、書き起こし遅延、取得不能、定例会の複数開催回、重複イベント、SSOT更新を検証する。自動起動を必須にするかは、研修運営者の選択に従って確定する。
