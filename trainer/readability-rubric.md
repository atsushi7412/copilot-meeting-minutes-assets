# 読みやすさ観察ルーブリック（F9・講師の独立観察・架空演習）

本書は議事録初稿の「読みやすさ」を講師が独立に観察するための項目である。全件架空。

## 重要な原則
- 読みやすさは content / entity / gate とは別の観察項目である。
- 読みやすさの観察結果を content の分母に足して 95% を押し上げてはならない（P2-⑦）。
- 本ルーブリックはローカルでは「項目・試料・記録欄の対応」だけを検査する。人による校正は未実施。

## 観察項目（各項目を 良い / 要改善 / 問題 で記録。採点の分母には入れない）
1. 冒頭把握：冒頭（状態・要旨）で会議の目的・主な結論・次の行動を短時間で把握できるか。
2. 条件と理由：議題別の議論で、合意に至った条件と理由を追えるか。
3. 未決の識別：未決事項・要確認事項が決定事項と視覚的・記述的に区別できるか。
4. 確定度を強めていないか：文章整理のために、未確定・暫定・候補を断定調へ強めていないか（読みやすさのために確定度を偽らない）。
5. 根拠へのたどりやすさ：決定・アクションから参照資料（発言時刻・段落・資料名）へたどれるか。
6. 冗長・重複：同じ内容の重複や不要な個人情報がないか。

## 校正試料（対応検査用・合成）
- 「正しいが読みにくい例」：内容は正確だが、要旨が長すぎ結論が埋もれ、未決と決定が同じ段落に混在する例。→ content/entity/gate は合格し得るが読みやすさは「要改善」。
- 「読みやすいが未確定を断定した例」：体裁は整い読みやすいが、未確定の「例の試作品」や候補所属を断定調で書いてしまった例。→ 読みやすさは「良い」に見えても、entity/gate では不合格（断定は誤り）。
この2試料で「読みやすさ」と「content/entity/gate の合否」が独立であることを確認する（読みやすさで合否を上書きしない）。
実本文は `trainer/readability-samples.md`（試料A=正しいが読みにくい例／試料B=読みやすいが未確定を断定した例）に掲載。観察項目1〜6と記録欄の対応例も同書末尾の表に示す。
